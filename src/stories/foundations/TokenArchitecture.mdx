# Token Architecture

Three tiers. Components reference **only** the middle tier — that indirection
keeps every button, focus ring, and surface consistent from one place instead
of scattered raw values. The tokens documented across every other Foundations
page (Color, Typography, Spacing & Sizing, Radius & Elevation) are all
instances of this same three-tier shape, defined once in `src/styles.css`.

## Naming convention

| Pattern | Example (real, in `styles.css`) | Rule |
|---|---|---|
| `--{category}-{value}` | `--sp-4`, `--r-md`, `--mo-slow` | Primitive spacing / radius / motion scales, a numeric or t-shirt step — never a raw pixel value inside component CSS |
| `--{role}` | `--color-action`, `--color-error` | Semantic color role, no numeric suffix — the role itself is the name |
| `--{role}-{modifier}` | `--color-error-hover`, `--color-action-surface` | A themed variant of a role: `hover` / `active` / `surface` (tint) / `text` (on-tint text) |
| `--{component}-{prop}` | `--btn-height-md`, `--modal-width-lg` | Component-scoped override, only introduced when tier 2 is insufficient |

## Where this lives

`src/styles.css` is the single source of truth — a Tailwind v4 `@theme` block,
not a separate JS config. Primitives sit in a plain `:root` block just above
it so they never leak into the generated utility set; every generated utility
(`bg-action`, `text-ink-700`, `p-sp-4`, `rounded-r-md`, …) is a semantic or
spacing/radius-scale name, never a raw primitive name.
