# Density & Themes

Try both switchers in the shell's utility bar (the user menu, top right).
Every token on every page re-points live — nothing below is a separate
stylesheet, it's the same semantic aliases resolving to different primitive
values via `<html data-theme="…">` / `<html data-density="…">`, applied by
`BaseThemeService` / `BaseDensityService`.

`<base-table>`'s own `[density]` input still wins when a module needs a
specific density regardless of the app-wide preference (e.g. an alarm log
that's always compact) — leaving it unset is what opts a table into the
global switcher via `BaseDensityService`.

## Themes

| Theme | When | Key differences from Light |
|---|---|---|
| **Light** <span style={{ fontSize: '10px', fontWeight: '700', padding: '2px 6px', borderRadius: '999px', background: 'var(--color-action-surface)', color: 'var(--color-action-hover)' }}>Default</span> | Default for all modules | — |
| **Dark** | Opt-in, persisted per user. Recommended for 24×7 control-room monitors | Semantic surfaces invert; brand/semantic hues shift lighter to hold contrast on a dark ground; shadows lose their color tint |
| **High contrast** | System-level HC mode (`prefers-contrast: more`), or manual opt-in, for glare and accessibility needs | Tints become solid white; borders go pure black at a heavier weight; shadows are removed in favor of borders; the focus ring widens `--focus-ring-width` 2px → 3px; icon stroke thickens `--icon-stroke-width` 2px → 3px |

A theme choice made explicitly in the switcher (including "Light") always
overrides the OS `prefers-contrast` signal — "Auto" is what leaves the door
open for the system setting to resolve High contrast on its own.
