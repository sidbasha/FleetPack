# Iconography

Icons **Outlined** exclusively — Material Symbols Outlined, loaded globally
in `index.html`. Every glyph below renders live via the `.icon-outline`
utility class (`src/styles.css`): a `<span>` whose text content is the
icon's name, e.g. `<span class="icon-outline">delete</span>`. No icon
*component* exists yet — this page is the foundation a future `<base-icon>`
builds on.

## Object icons: Tool, Fleet & Chamber

These three nouns are the spine of the product, so their glyphs carry more
weight than any other icon in the set — three distinguishable glyphs for
three distinguishable hierarchy levels, applied the same way everywhere.

| Object | Why it changed |
|---|---|
| Tool | A microchip icon is what runs *inside* equipment, not the equipment itself — `monitor` reads as the equipment front, unambiguous below 16px |
| Fleet | A server-rack icon is IT infrastructure, not a group of fab tools — `workspaces` reads as "several grouped units" instead |
| Chamber | Unchanged — freed up by the Tool change, since nothing else in the set meant "a module inside a tool" |

Added to the library alongside this pass: `description` (recipe),
`build` (maintenance — already in Actions/Status above), `blur_circular`
(wafer), `deployed_code` (a packaged/deployed module, chamber's process
alternate).

## Color & state rules

| Rule | Detail |
|---|---|
| Inherit by default | Icons take `currentColor` unless carrying independent semantic meaning (e.g. a fixed error-red delete icon). |
| Never color-only | A status icon always ships with a text label or pairs with color rather than color alone. |
| Filled = active | Fill marks the active/selected state of a toggleable icon; outlined is resting. |
