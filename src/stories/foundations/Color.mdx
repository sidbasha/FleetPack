## Tint pairings

Fill vs. text — the tint (`*-surface`) is the background, the full-strength
token is the text/icon sitting on it. `solid-*` is the inverse: full-strength
fill with white text, for a primary action rather than a passive status chip.

## Usage guidelines

| Token | Use for | Never for |
|---|---|---|
| `action` | Primary buttons, active nav, links, focus rings, selected rows | Status/severity meaning |
| `accent` | Secondary chart series, highlights, badges distinct from Action | Primary CTAs — reserved for Action |
| `success` | Completed/executed states, positive trend, confirmation | Decorative accents unrelated to a positive outcome |
| `warning` | Pending states, non-fatal alarms, caution banners | Critical or blocking errors — use Error instead |
| `error` | Fatal alarms, failed operations, destructive confirmation | Warnings that are recoverable |
| `info` | Neutral banners, data-integrity category, tooltips | Anything requiring user action |
| `neutral` | Disabled state, secondary text, dividers, unselected chips | Any semantic or interactive meaning |

## Machine state

FleetPack's state vocabulary is the SEMI E10 equipment-state model, not a
parallel invention — every FleetPack label below maps to one E10 state and
one semantic token, defined once in `styles.css`, re-keyed everywhere a state
renders (badges, dots, heatmap cells, Gantt segments) instead of living as a
second palette.

| SEMI E10 state | FleetPack label | Token | Counts toward |
|---|---|---|---|
| Productive Time | Production | `success` | Up-time · availability numerator |
| Standby Time | Standby | `accent` | Up-time, not production |
| Engineering Time | Engineering | `action` | Up-time, excluded from OEE |
| Scheduled Downtime | Scheduled DT | `warning` | Downtime · planned |
| Unscheduled Downtime | Unscheduled DT | `error` | Downtime · unplanned, drives MTTR |
| Non-Scheduled Time | Non-scheduled | `neutral` | Excluded from every availability figure |
| *Not an E10 state* | Gap / no data | `neutral` (`border-default`) | Nothing — telemetry is missing, which is not a state |

## State differentiation

Six states sit side by side in a 24-hour Gantt at eighteen pixels tall, often
under cleanroom lighting that shifts hue perception — so hue alone never
carries the meaning. Every state also carries a fill pattern and, wherever it
renders as a badge, its own glyph.

| Adjacent pair | Hue contrast | Second cue that separates them |
|---|---|---|
| Production ↔ Standby | 2.1:1 | Both solid, so the badge glyph and label carry it |
| Standby ↔ Engineering | 1.4:1 | The closest pair in the set |
| Scheduled ↔ Unscheduled DT | 2.0:1 | Opposing hatch angles plus distinct glyphs |
| Any downtime ↔ any up-time | ≥ 3.4:1 | Hatched against solid |

| State | Hue | Pattern | Glyph |
|---|---|---|---|
| Production | `success` | Solid — processing wafers | `check_circle` |
| Standby | `accent` | Solid — able to run, idle | `pause_circle` |
| Engineering | `action` | Solid — qualification or test | `build` |
| Scheduled DT | `warning` | Hatch 45° — planned maintenance | `event` |
| Unscheduled DT | `error` | Hatch 135° — fault or interlock | `warning` |
| Non-scheduled | `neutral` | Dotted — outside the operating calendar | `bedtime` |
| Gap / no data | `neutral` | Dotted — telemetry missing | `help` |

Live in `<base-state-heatmap>` / `<base-gantt-timeline>`: hue and pattern
render on every cell/segment; the legend adds the glyph, so all three layers
are demonstrated together, not just described.
